## Autonomous Vehicle V2V Communication Simulator

### Section 1: Fundamentals of V2V & Network Simulation

1. **What is Vehicle-to-Vehicle (V2V) Communication?**  
   *Answer*: V2V is wireless communication between connected vehicles allowing real-time exchange of safety telemetry (speed, braking, position) to prevent collisions and coordinate platooning.

2. **Why is NS-2 used in this project?**  
   *Answer*: NS-2 is a proven, discrete-event network simulator providing exact packet scheduling, queue management (DropTail/RED), transport protocols, and 12-column trace logs.

3. **What is a node in NS-2?**  
   *Answer*: A network entity (e.g. an autonomous vehicle, router, or RSU) that hosts protocol agents and connects to duplex links.

4. **What is a packet in NS-2?**  
   *Answer*: A discrete unit of data with a header (flow ID, sequence number, source/destination address, size) and payload scheduled at specific simulation timestamps.

5. **What is a trace file (`.tr`)?**  
   *Answer*: A chronological text log generated by NS-2 recording every packet event (`+` enqueue, `-` dequeue, `r` receive, `d` drop) across all nodes and links.

6. **What is a NAM file (`.nam`)?**  
   *Answer*: A Network Animator visualization file recording graphical layout, node coordinates, packet flows, and color-coded packet animations.

7. **What standard governs physical V2V communication?**  
   *Answer*: IEEE 802.11p Dedicated Short-Range Communications (DSRC) and 3GPP Cellular V2X (C-V2X) in the 5.9 GHz band.

8. **What is the maximum latency threshold for V2V emergency safety alerts?**  
   *Answer*: Active safety messages (Emergency Collision Warnings) require an end-to-end dissemination latency of strictly less than **50 milliseconds**.

### Section 2: Routing Protocols (Dijkstra vs. Distance Vector)

9. **What is Dijkstra's algorithm?**  
   *Answer*: A greedy, centralized Link-State algorithm that computes the single-source shortest path tree on a graph with non-negative edge weights.

10. **What is Distance Vector routing?**  
    *Answer*: A distributed, iterative algorithm based on Bellman-Ford where nodes exchange distance estimates with direct neighbors until convergence.

11. **What is the fundamental difference between Dijkstra and Distance Vector?**  
    *Answer*: Dijkstra requires global knowledge of the entire network topology (via Link State Advertisements), while Distance Vector relies only on local estimates received from direct neighbors.

12. **What is the Bellman-Ford update equation?**  
    *Answer*: $D_x(y) = \min_v \{ c(x, v) + D_v(y) \}$, where $c(x, v)$ is the link cost to neighbor $v$, and $D_v(y)$ is $v$'s distance to $y$.

13. **What is the time complexity of Dijkstra's algorithm?**  
    *Answer*: $O(V^2)$ with an adjacency matrix/array, or $O((E + V)\log V)$ with a binary min-heap / priority queue.

14. **What is the "Count-to-Infinity" problem?**  
    *Answer*: A routing loop in Distance Vector where disconnected nodes slowly increment distance metrics to infinity due to mutually dependent routing updates.

15. **How does Poison Reverse resolve Count-to-Infinity?**  
    *Answer*: If node $A$ routes to destination $D$ through neighbor $B$, $A$ advertises $D_A(D) = \infty$ to $B$, preventing $B$ from ever attempting to route to $D$ via $A$.

16. **What is Split Horizon?**  
    *Answer*: A rule stating that a router must not advertise a route back out of the same interface from which it learned that route.

17. **Why is Dijkstra faster to reconverge after a vehicular link failure?**  
    *Answer*: Dijkstra recalculates routes immediately in 1 step once a new LSA is flooded, whereas Distance Vector takes multiple synchronous iteration rounds to propagate updates.

18. **What is routing overhead?**  
    *Answer*: The ratio of non-payload control packets (LSAs or Distance Vectors) transmitted across the network to maintain routing tables.

### Section 3: Error Detection & CRC

19. **What is CRC (Cyclic Redundancy Check)?**  
    *Answer*: A polynomial-based error-detecting code that uses bitwise modulo-2 division to generate a Frame Check Sequence (FCS) appended to transmitted data.

20. **Why is CRC preferred over simple parity in wireless V2V networks?**  
    *Answer*: Simple parity only detects single-bit errors. CRC detects 100% of all single-bit, double-bit, odd-numbered bit errors, and burst errors of length $\le r$ bits.

21. **What is the generator polynomial for CRC-16-CCITT?**  
    *Answer*: $G(x) = x^{16} + x^{12} + x^5 + 1$ (Hex: `0x1021`, Binary: `10001000000100001`).

22. **What is the generator polynomial for CRC-32-IEEE 802.3?**  
    *Answer*: $G(x) = x^{32} + x^{26} + x^{23} + x^{22} + \dots + 1$ (Hex: `0x04C11DB7`).

23. **How does modulo-2 division differ from standard arithmetic division?**  
    *Answer*: Modulo-2 arithmetic uses XOR operations without carries or borrows ($1 \oplus 1 = 0$, $1 \oplus 0 = 1$, $0 \oplus 0 = 0$).

24. **How does the receiver verify a frame with CRC?**  
    *Answer*: The receiver divides the entire received bitstream (Data + FCS) by the generator polynomial. If the remainder (syndrome) is zero, the frame is accepted; otherwise, it is rejected.

25. **What is a burst error?**  
    *Answer*: Consecutive corrupted bits in a frame caused by short-duration electromagnetic interference or multipath fading.

26. **What happens in our simulator when CRC detects an error?**  
    *Answer*: The receiver discards the corrupted frame, marks a CRC error in the log, and withholds acknowledgement, prompting ARQ retransmission.

### Section 4: Flow Control & ARQ Protocols

27. **What is Flow Control?**  
    *Answer*: A set of mechanisms ensuring a fast transmitting sender does not overwhelm the processing or buffer capacity of a slower receiver.

28. **What is Sliding Window flow control?**  
    *Answer*: A protocol where the sender can transmit up to $W$ frames before waiting for an acknowledgement, with the window advancing as ACKs arrive.

29. **What is Stop-and-Wait ARQ?**  
    *Answer*: A special case of sliding window where window size $W = 1$, meaning the sender transmits one frame and must wait for an ACK before sending the next.

30. **What is Go-Back-N (GBN) ARQ?**  
    *Answer*: A sliding window protocol where the receiver accepts only strictly in-order frames, and on timeout, the sender retransmits all unacknowledged frames starting from the oldest missing frame.

31. **What are Cumulative Acknowledgements?**  
    *Answer*: An ACK containing sequence number $K$ indicates that all frames up to and including $K$ have been received correctly.

32. **Why does GBN discard out-of-order frames?**  
    *Answer*: To keep receiver buffer requirements minimal ($W_R = 1$) and avoid complex reordering buffers on resource-constrained onboard vehicle computers.

33. **What is the maximum window size in GBN for $m$-bit sequence numbers?**  
    *Answer*: $W_{\max} = 2^m - 1$, preventing ambiguity between current and subsequent window cycles if all ACKs are lost.

34. **What is Selective Repeat ARQ, and how does it differ from GBN?**  
    *Answer*: Selective Repeat buffers out-of-order frames at the receiver ($W_R = W_S$) and retransmits ONLY the specific frames that were lost, rather than the entire window.

35. **What is protocol efficiency ($\eta$)?**  
    *Answer*: The ratio of useful successfully delivered data frames to the total number of frames transmitted including retransmissions ($\eta = \frac{N_{\text{useful}}}{N_{\text{total}}}$).

### Section 5: Congestion Control & Performance Metrics

36. **What is network congestion?**  
    *Answer*: A state occurring when offered traffic load exceeds link capacity, causing queue buffer buildup, excessive delays, and packet drops.

37. **What is Packet Delivery Ratio (PDR)?**  
    *Answer*: $\text{PDR} = \left(\frac{\text{Total Packets Delivered at Destinations}}{\text{Total Packets Generated at Sources}}\right) \times 100\%$.

38. **What is Packet Loss Ratio (PLR)?**  
    *Answer*: $\text{PLR} = \left(\frac{\text{Total Packets Lost}}{\text{Total Packets Generated at Sources}}\right) \times 100\% = 100\% - \text{PDR}$.

39. **What is Throughput?**  
    *Answer*: The total volume of payload data successfully delivered across the network per unit of simulation time, expressed in Kbps or Mbps.

40. **What is End-to-End Latency?**  
    *Answer*: The time elapsed from when a packet leaves the source application layer to when it arrives at the destination application layer ($t_{\text{recv}} - t_{\text{send}}$).

41. **What is Jitter?**  
    *Answer*: The statistical variation or fluctuation in end-to-end packet transit delay between consecutive received packets ($|\text{Delay}_{i+1} - \text{Delay}_i|$).

42. **Why does latency increase dramatically during congestion?**  
    *Answer*: Packets spend significant time waiting in link queue buffers (queuing delay) before being served by the transmission interface.

43. **What is AIMD (Additive Increase Multiplicative Decrease)?**  
    *Answer*: A congestion control algorithm that linearly increases sending rate when no loss occurs, and halves/multiplicatively cuts the sending rate upon detecting packet loss.

44. **What is Slow Start in TCP?**  
    *Answer*: An initial probing phase where the congestion window ($cwnd$) doubles every round-trip time (exponential growth) until reaching $ssthresh$.

45. **What is Fast Retransmit in TCP Reno?**  
    *Answer*: Retransmission of a lost segment immediately upon receiving 3 duplicate ACKs without waiting for the retransmission timer to expire.

46. **What is Fast Recovery in TCP Reno?**  
    *Answer*: Setting $ssthresh \gets cwnd / 2$ and $cwnd \gets ssthresh + 3$, skipping Slow Start and directly resuming linear Congestion Avoidance.

47. **What is a DropTail queue?**  
    *Answer*: A simple FIFO queue discipline where incoming packets are dropped immediately when the queue buffer reaches its maximum capacity.

48. **What are the 3 V2V safety message classes in our project?**  
    *Answer*: (1) `COLLISION_WARNING` (high priority, 128B), (2) `SUDDEN_BRAKING` (high priority, 256B), and (3) `TRAFFIC_INFORMATION` (normal priority, 512B).

49. **How does our project enforce message priority?**  
    *Answer*: Critical safety messages are assigned higher flow IDs, shorter transmission intervals, and lower queuing latency, ensuring delivery within 15.81 ms.

50. **What command runs the entire project and reproduces all results?**  
    *Answer*: `./run_all.sh` executes the entire suite from scratch in under 30 seconds.
